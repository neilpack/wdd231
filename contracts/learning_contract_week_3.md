# Learning Contract: Improve Responsive and Inclusive Presentation

Student: Neil Pack  
Date: October 2, 2026  
Target assessment date: October 8, 2026

## Primary competency

By the end of this contract, I will be able to:

I can create a responsive and inclusive web page that remains readable, usable, and visually organized at narrow and wide viewport sizes. I can explain how my Flexbox or Grid layout, spacing, typography, color contrast, image handling, and accessibility choices support different users and devices.

## My starting point

I already know/can:

I can create a basic web page with HTML, CSS, and JavaScript, use data to generate repeated game-announcement content, and create a simple mobile-first page structure. I can apply CSS selectors and basic layout styles, but my responsive design and accessibility testing need to become more intentional.

I still need to learn or improve:

- Choosing between Flexbox and Grid for different layout problems.
- Creating a mobile-first layout that works at narrow, medium, and wide widths.
- Using typography, spacing, and visual hierarchy to make announcements easy to scan.
- Organizing shared styles with custom properties and reusable component styles.
- Making long game titles, descriptions, and differently sized images fit without breaking the layout.
- Checking color contrast, text size, reflow, zoom, text enlargement, motion, and touch-target size.

## My learning plan

I will use these resources:

- MDN Web Docs documentation for CSS Flexbox, CSS Grid, media queries, custom properties, and responsive images.
- Browser developer tools for testing viewport sizes, zoom, reflow, contrast, and layout behavior.
- Feedback from a peer, instructor, or teaching assistant during a visual review of the page.

I will practice by:

I will improve my web app so users look at fictional hikes. I will build a mobile-first layout using Flexbox or Grid, add responsive breakpoints, define shared colors and spacing with CSS custom properties, and style announcement cards with readable typography and clear visual hierarchy. I will test long titles, long descriptions, missing or differently sized images, and several viewport sizes. I will also check contrast, zoom, reflow, text enlargement, motion, and touch-target sizing, then document at least one problem from diagnosis through its fix.

My first milestone, due October 4, 2026, is:

I will create the mobile-first page structure and responsive card layout. The layout will work at a narrow mobile width and a wider desktop width, use either Flexbox or Grid intentionally, and include custom properties for repeated colors, spacing, and typography values.

## Evidence of learning

I will submit or demonstrate:

- A working page shown at narrow, medium, and wide viewport sizes.
- Screenshots or a live demonstration (during a peer review) showing the responsive layout and explanation of why I selected Flexbox or Grid.
- A contrast check, including any color correction I made to improve readability.
- A reflow, zoom, and text-enlargement check showing that content remains usable.
- A test showing that long text and differently sized or missing images do not break the layout.
- A short explanation of one responsive or accessibility problem, how I diagnosed it, the fix I made, and what I learned.

I will know I am ready when:

- The page remains readable and usable at narrow and wide viewport sizes without horizontal scrolling or overlapping content.
- My colors meet an acceptable contrast standard, and I can explain any changes I made.
- The layout continues to work when text is enlarged, the page is zoomed, descriptions are long, or images have different dimensions.

## Support and risks

The help I may need is:

I may ask a peer or instructor to review the page at different viewport sizes and point out readability, spacing, contrast, or interaction problems that I do not notice myself. I may also use MDN documentation when I am unsure whether Flexbox, Grid, or a media query is the best solution.

A risk to my plan is:

A likely obstacle is spending too much time adjusting visual details without testing the actual layout behavior. I will respond by testing one change at a time at specific viewport sizes, keeping a short record of problems and fixes, and prioritizing readability, accessibility, and functionality before decoration.

## AI use, if applicable

I expect to use AI for:

I may use AI for brainstorming layout approaches, explaining CSS properties, suggesting possible debugging ideas, and reviewing small code sections. I will write, adapt, and understand the final implementation myself.

I will verify AI suggestions by:

I will compare suggestions with MDN documentation, test the code in my own project, inspect the result in browser developer tools, and verify the page at multiple viewport sizes. I will not count a suggestion as evidence until I can explain why it works and confirm that it improves the page.
